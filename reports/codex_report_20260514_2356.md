## 実施した作業

## 調査内容

- `rg` で `TEXT_LLM_PROVIDER`、`OPENAI_MODEL`、`call_gemini_text`、`call_openai_text`、`IMAGE_PROMPT_LLM_PROVIDER`、`QUALITY_CHECK_LLM_PROVIDER` などを検索した。
- 実装ファイル内には、X 投稿本文生成、OpenAI/Gemini クライアント、provider 分岐、画像プロンプト生成、品質チェックのコードは見つからなかった。
- 既存実装は主に `training_app.html` と docs / reports であり、BUG-001 の対象となる runtime code は未実装だった。
- 未追跡の `discord_export_to_csv.py` は今回の provider 修正範囲外のため触っていない。

## 原因

- 現リポジトリには、`TEXT_LLM_PROVIDER` を単一箇所で解決して本文生成関数へ渡す実装がなかった。
- そのため、docs に記録された BUG-001 は「既存コードの該当箇所を修正」ではなく、「provider 混線を防ぐ共通ルーティング層を新設して今後の実装で使う」対応が必要な状態だった。
- 過去の事象としては、設定解決経路の分散、デフォルト分岐、GUI 値と実行時参照先の不一致が原因候補。

## 修正内容

- `x_auto_ops/provider_routing.py` を追加。
  - `resolve_runtime_config()` で GUI/env 由来の設定を単一の `RuntimeConfig` に解決。
  - 本文生成は `TEXT_LLM_PROVIDER` を参照。
  - 画像プロンプト生成は `IMAGE_PROMPT_LLM_PROVIDER` を参照。
  - 品質チェックは `QUALITY_CHECK_LLM_PROVIDER` を参照。
  - provider と実際の低レベル関数が一致しない場合は `ProviderMismatchError` で停止。
  - 呼び出し直前に `provider` / `model` / `called_function` / `account_id` / `purpose` をログへ出す。
  - 実 API クライアントは内蔵せず、provider 関数を注入する形にした。
- `tests/test_provider_routing.py` を追加。
  - すべてモック関数で検証し、実 API は呼んでいない。
- `docs/BUG_HISTORY.md` を更新。
  - BUG-001 の調査結果、修正内容、追加テスト、関連ファイルを追記。
- `docs/DEVELOPMENT_RULES.md` を更新。
  - 本文生成、画像プロンプト生成、品質チェックの provider を個別解決するルールを追記。

## 追加テスト

- `TEXT_LLM_PROVIDER=openai` のとき、本文生成で `call_openai_text` だけが選ばれること。
- `TEXT_LLM_PROVIDER=gemini` のとき、本文生成で `call_gemini_text` だけが選ばれること。

- provider と called function が不一致の場合に `ProviderMismatchError` で停止すること。
- ログに `provider` / `model` / `called_function` が含まれること。
