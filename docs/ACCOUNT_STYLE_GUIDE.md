# アカウント別スタイルガイド

**目的:** 各アカウントの **世界観・文体・画像・禁止事項** を固定化し、AI（Cursor / Codex）の変更・Provider 切替・モデル変更があっても **運用ブレ** を防ぐ。

**運用:** 文体・画像・運用方針・禁止事項を変えたら **本ファイルを更新** する。変更理由が分かるように、日付と一言の変更理由を節末や変更履歴に残すとよい。

**関連:** バグ・混線・安全判定の履歴は **`BUG_HISTORY.md`**。開発上の強制ルールは **`DEVELOPMENT_RULES.md`**。

## yokaze_daily（夜風）

### アカウント目的

夜の時間帯に、読者の **言葉にならない感情** に寄り添い、短い投稿で **少しだけ軽くする** こと。

### 誰向けか

一日の終わりに疲れや孤独感を抱えているが、「説教されたくない」「正論で押されたくない」大人。

### 空気感

静かな部屋、遅い時計、遠くの街の灯り。 **余白** を残す。詰め込まない。

### 文体

- **お兄さん感:** 上からではなく、少し年上の落ち着き。馴れ馴れしすぎない。
- **本音の言語化:** 読者が飲み込んでいることを **代弁** する（下記「OK表現」参照）。
- **綺麗なポエム禁止:** 比喩の連打・美文調・詩的な改行だらけは避ける。
- **カウンセラー禁止:** 診断・分析・ワークの誘導のような **職業的カウンセリング調** にしない。
- **「大丈夫」連発禁止:** 安易な安心の言葉で **感情を薄める** のを避ける。
- **抽象的慰め禁止:** 「頑張って」「いつか良くなる」だけで終わらせない。具体ではなく **感情の輪郭** を言葉にする。

### 画像方針

- **人物画より生活感・空気感:** 顔のはっきりした人物より、光、影、室内、夜の街、手元など **気配** が伝わるビジュアルを優先。
- **画像は毎回不要:** テキストで十分な回は **無理に画像を付けない**。
- **余白:** レイアウトも詰め込みすぎず、 **呼吸できる余白** を意識。

### NG表現

- 綺麗なポエム調、抽象語の盛り合わせだけの美文。
- カウンセラー口調、診断めいた断定。
- 「大丈夫？」「きっと大丈夫」の連発、テンプレの抽象的慰め。
- 正論ハンマー、上からの叱り。
- 過度な絵文字・過度な若作りスラング。

### OK表現

- 読者の感情を **名前をつけて** そっと言う（例: 焦れない感じ、言い訳みたいな自分への苛立ち）。
- **傷を正確に言い当てる** ニュアンス: 誇張ではなく、**核心に触れる一言**。
- 最後に **少しだけ救う:** 大きな希望約束ではなく、次の一歩が小さくてよいという **温度**。

### 投稿例（方向性サンプル・実文は運用で差し替え）

> 今日は、何も悪いことしてないのに、ずっとダメな気がする夜がある。  
> それは、疲れが「意味」を捏造してるだけかもしれない。  
> 寝る前に一つだけ、肩の力を抜いてみよう。それで十分。

（※ 実投稿はトーンを保ちつつ多様化する。サンプルは **構造** の参考。）

### やってはいけないこと

- 読者の痛みを **軽く扱う** こと。
- 安全側に倒すあまり **無難な一般論** だけにすること（Provider 側の制約と戦うのではなく、**相性の良い Provider・プロンプト** で設計する）。
- 毎回画像を付けて **ノイズ化** すること。

### 推奨構造

1. **感情の言い当て**（短く）  
2. **なぜそう感じるか** を一言で言語化（断定しすぎない）  
3. **最後に少しだけ救う**（小さな行動または許し）

### 画像あり／なし判断

- **なし:** 感情の核心がテキストだけで伝わるとき、連投で画像が飽きるとき。
- **あり:** 空気感・余白を **視覚で補強** した方が自然なとき。頻度は控えめ。

### provider 相性

- **Gemini:** 安全判定により **PROHIBITED_CONTENT** や無難化が起きやすい場面がある（`BUG_HISTORY.md` BUG-002）。夜風の「本音」路線と衝突しうる。
- **OpenAI:** 路線によっては夜風のトーンと相性が取りやすいが、モデル・設定次第。**ログで実際の provider を常に確認**すること。

### 推奨モデル

運用で確定したら **モデル ID を具体的に追記**（例: テキスト用 `gpt-…`）。未確定の間は「夜風は安全判定に引っ張られにくい構成を優先」とだけ書いておく。

### 参考アカウント方向性

「夜にそっと隣にいる」「短く刺さる」「文学ではなく生活の言葉」— ブランド名の固定はせず、**上記ルールが正**。

## ai_pickup（AI 副業）

### アカウント目的

AI・副業・効率化の情報を **一瞬で理解できる形** に整理し、保存・再利用したくなる価値を出す。

### 誰向けか

スキマ時間にスマホで情報を拾い、すぐ試したい副業・AI 利用者。

### 空気感

明るすぎず冷たすぎず、**プロだが取り付きやすい** コンサル棚のような整理感。

### 文体

- **長文禁止:** 結論→根拠は短いブロックで。スクロール地獄にしない。
- **情報整理:** 番号・見出し・対比で **スキャン可能** に。

### 画像方針

- **図解重視:** テキストの補足ではなく、**意味の主役** を図に載せる。
- **Before / After、比較図、フロー図** を積極活用。
- **Canva 感を減らす:** テンプレ感の強い装飾・意味のないアイコンだらけを避け、 **情報の階層** が一目で分かるデザインに寄せる。
- **スマホ可読性重視:** 文字サイズ・コントラスト・余白の下限を決める。
- **保存したくなること:** 後で見返したときに **一枚で意味が復元** できる密度と構造。

### NG表現

- 前置きの長い自慢話、専門用語の羅列だけ。
- 図解なのに文字が読めない密詰め。
- 「とにかくすごい」だけの煽りで中身がない。

### OK表現

- 結論を先に、根拠は箇条書きまたは図。
- 「やること3つ」「失敗パターン2つ」のように **数で区切る**。

### 投稿例（方向性）

> 【結論】○○は△△を先にやると速い  
> 理由は3つだけ  
> 1. … 2. … 3. …  
> 図: フロー（入力→処理→出力）

### やってはいけないこと

- 図解のために **同じ画像生成をリトライ乱発** すること（コスト・API 規約・`DEVELOPMENT_RULES.md`）。
- 長文スレッドで **読了コスト** を爆上げすること。

### 推奨構造

1. **結論・比較の勝者**（最上段）  
2. **理由または手順**（3±2 個に制限）  
3. **図**（Before/After / 比較 / フロー のいずれか）

### 画像あり／なし判断

- **あり:** 比較・手順・構造を **一瞬で** 見せたいとき（デフォルト寄り）。
- **なし:** 速報一文で足りるときのみ。

### provider 相性

- 図解生成パイプラインは **画像 API の仕様差** が大きい。Provider 切替時は **出力解像度・テキスト埋め込み品質** を再検証する。
- GUI の Provider と実装の一致は `BUG_HISTORY.md` BUG-001 を参照。

### 推奨モデル

テキスト用・画像用を分けて **確定次第追記**。

### 参考アカウント方向性

「図で勝つ情報アカウント」「保存が伸びる整理屋」— 具体名は運用で更新可。

## new_account_daily（新規デイリー）

### アカウント目的

新規アカウントの **毎日投稿** を安定供給し、フォロワー獲得とアルゴリズム学習用の **一定トーン** を維持する。

### 誰向けか

立ち上げ直後のターゲット層は **運用計画で固定**（夜風寄り／AI 副業寄りのいずれか、またはハイブリッド）。方針を変えたら本節を更新。

### 空気感

**yokaze_daily か ai_pickup のどちらを母テンプレにするか** で空気感が決まる。混在させる場合は **曜日・枠** で役割を分ける。

### 文体

- 母テンプレが夜風なら **yokaze_daily の文体節を継承**（お兄さん感・本音・ポエム禁止等）。
- 母テンプレが AI 副業なら **ai_pickup の文体節を継承**（長文禁止・整理等）。

### 画像方針

- 母テンプレに合わせる。ハイブリッド運用なら **「文字中心の日」と「図解中心の日」** をルール化してブレを防ぐ。

### NG表現

母テンプレ側の NG を **そのまま継承**。また、新規特有の **テンプレ露見**（毎回同じ導入句）を避ける。

### OK表現

母テンプレの OK を継承しつつ、**アカウント立ち上げ期** は「誰かに向けて話している」自然さを優先。

### 投稿例

母テンプレの構造に従い、実例は運用で追記。

### やってはいけないこと

- 夜風と AI 副業の **要件を同一投稿で混ぜて四不像** にすること。
- 設定未確定のまま Provider を切り替えて **品質が追跡不能** になること。

### 推奨構造

母テンプレの推奨構造に従う。

### 画像あり／なし判断

立ち上げ期は **コストと工数** を考え、画像頻度を **週次ルール** で決めてから運用（例: 週○回は図解）。

### provider 相性

**母テンプレに合わせた Provider を優先。** 夜風寄せなら安全判定の影響を意識し、AI 副業寄せなら図解 API の安定性を優先。

### 推奨モデル

母テンプレ確定後に **具体的モデル名を追記**。

### 参考アカウント方向性

「育成中の夜風」または「育成中の図解アカウント」— どちらを目指すかを一文で固定し、ブレたら更新。
