# バグ履歴（再発防止）

**目的:** 過去の不具合について、原因・修正・影響・再発防止策を **同じ形式** で蓄積し、Cursor / Codex / 人間が共有参照できるようにする。チャットや口頭の記憶に依存しない。

**運用:** 新しい重大バグ、API 暴走、Provider 混線、誤生成が発生したら **本ファイルに追記** する。既存エントリの改ざんは避け、訂正は「追記で訂正」とするか該当行に注記する。

---

## 記載ルール（各バグごとに必須）

各エントリに、最低限次を含める。

| 項目 | 説明 |
|------|------|
| **日付** | 事象の発生日、または不明なら **本履歴への初回記録日** とその旨 |
| **発生内容** | ユーザー視点・システム視点での症状 |
| **発見方法** | ログ、監視、レビュー、ユーザー報告など |
| **原因** | 確定／推定を明記 |
| **影響範囲** | アカウント、機能、課金、データ |
| **修正内容** | コード・設定・運用の変更要約 |
| **追加したテスト** | モック／実 API 別 |
| **再発防止策** | 設計・ゲート・ドキュメント |
| **関連ファイル** | パスまたはモジュール名（不明なら「要追記」） |
| **関連 provider** | openai / gemini / その他 |
| **実 API 消費有無** | あり／なし／不明 |

**なぜこの粒度か:** 「原因だけ」のメモは同じパターンで再発する。テストと再発防止までセットで残すと、別ツールが読んでも対応の継続性が保てる。

## BUG-001: `TEXT_LLM_PROVIDER=openai` なのに `call_gemini_text()` が呼ばれた

| 項目 | 内容 |
|------|------|
| **日付** | 2026-05-14（本履歴への初回記録。事象の発生日時は運用ログで要確認） |
| **発生内容** | 環境変数または設定で `TEXT_LLM_PROVIDER=openai` としているにもかかわらず、本文生成処理で **`call_gemini_text()`** が実行された疑い・事実があった。GUI 上の選択と内部呼び出しが一致していなかった。 |
| **発見方法** | ログ・トレース・コードレビュー、または出力品質の違和感からの調査（具体手順は関連コミット・PR に紐づけて追記推奨）。 |
| **原因（推定含む）** | **設定の読み取り経路が複数**ある、デフォルト分岐が Gemini 側に落ちる、GUI の保存先と実行時の参照先が不一致、リファクタ後の呼び出し名の取り違え、など。コードベース確定後に「確定」へ更新すること。 |
| **影響範囲** | **夜風（yokaze_daily）を含む本文生成全般:** 意図した OpenAI 系の文体・温度感と異なる **Gemini 寄りの無難な文章** が出る可能性。**API 消費** が想定外に増える。品質レビューで「なぜブレるか」調査の **無駄な反復** が発生。 |
| **修正内容** | 単一の **設定解決レイヤ** で `provider` / `model` を決定し、呼び出し直前にログを出す。GUI 値と実インスタンスの不一致は **エラーまたは起動失敗** にする方針（`DEVELOPMENT_RULES.md` 参照）。該当する具体的パッチは関連ファイルに紐づけて追記。 |
| **追加したテスト** | `TEXT_LLM_PROVIDER=openai` 時に **Gemini テキスト関数が呼ばれない** ことをモックで検証。設定解決関数のユニットテスト。 |
| **再発防止策** | `provider` / `model` / `called_function` の **構造化ログ** を必須化。PR では設定のデータフローを文章化。`ACCOUNT_STYLE_GUIDE.md` の provider 相性と矛盾しないよう設定画面のラベルを揃える。 |
| **関連ファイル** | 要追記（本文生成ルート、設定読込、`.env` ドキュメント） |
| **関連 provider** | 想定: **OpenAI**。実際に呼ばれた: **Gemini**（テキスト）。 |
| **実 API 消費有無** | **あり**（誤ルートで Gemini が呼ばれた場合、および再試行が重なった場合）。 |

## BUG-002: Gemini 安全判定による `PROHIBITED_CONTENT` 問題

| 項目 | 内容 |
|------|------|
| **日付** | 2026-05-14（本履歴への初回記録。事象の発生日時は運用ログで要確認） |
| **発生内容** | 夜風アカウント向けの **感情表現・本音寄りのコピー** が、Gemini 側の **安全フィルタ／ポリシー** に抵触し、応答がブロックされたり、**無難化・丸め込み** が強くかかった。エラーまたは警告として `PROHIBITED_CONTENT` 系の分類が返るケースがあった。 |
| **発見方法** | API レスポンスのエラーコード・フィニッシュ理由のログ、生成文の急なトーン変化、投稿レビューでの「急に丁寧語・抽象慰め」への変化。 |
| **原因** | **プロバイダの安全設計** と、夜風路線が求める **生の言語化** が衝突。プロンプト側の迂回避けが不十分、またはそもそも **夜風に Gemini を使う相性** が悪い運用だった可能性。 |
| **影響範囲** | **夜風（yokaze_daily）** を中心に、感情表現の強い投稿パイプライン。投稿欠損、リトライによる **API 増加**、編集の手戻り。 |
| **修正内容** | （例）夜風本文は **OpenAI 側を優先**、プロンプトで過激な表現を **攻撃性と誤認されない** 書き方に調整、ブロック時は **人間レビュー待ち** にフォールバックして自動無難化を避ける、など。確定した対策を追記。 |
| **追加したテスト** | 安全判定が返る入力の **フィクスチャ** をモックし、リトライ・フォールバックが暴走しないことを検証。 |
| **再発防止策** | `ACCOUNT_STYLE_GUIDE.md` の **provider 相性** を運用と一致させる。安全判定ログを **アラート** にする。リトライ乱発禁止（`DEVELOPMENT_RULES.md`）。 |
| **関連ファイル** | 要追記（Gemini クライアント、プロンプトテンプレ、夜風用設定） |
| **関連 provider** | **Gemini**（安全判定・コンテンツフィルタ） |
| **実 API 消費有無** | **あり**（ブロック前の試行、リトライが重なると増幅）。 |
